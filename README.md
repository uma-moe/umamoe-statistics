# Uma.moe Statistics Generator

Standalone Rust port of `scripts/statistic.py` for weekly Team Stadium statistics builds.

The generator is designed for the big table case: it streams rows from PostgreSQL with `COPY`, keeps only aggregate counters in memory, and writes the same frontend-facing layout:

```text
statistics/
├── datasets.json
└── {dataset}/
    ├── index.json
    ├── global/global.json
    └── characters/{character_id}.json
```

Generated datasets use the ID-only format marked by `format: "ids-v1"` and `format_version: 4` in `datasets.json`, each dataset `index.json`, and per-file metadata. Older datasets without this marker are legacy name-resolved statistics.

Only trainers with `team_evaluation_point > 2500` contribute to new exports. Trainers at or below 2500, trainers with a null evaluation, and stadium rows without a matching trainer are excluded before applying `--limit`. This filter applies to every count and breakdown; it does not delete database records or change previously exported datasets.

Stat histograms keep 20 buckets and expand to cover the observed values for each report, including stats above 1200 and rank scores above 17,000. Reports within the original ranges keep their existing bucket boundaries. Consumers should read the supplied range labels instead of assuming a fixed maximum.

## Source layout

The project stays a single Cargo package. `src/main.rs` only declares modules and starts the CLI.

- `src/cli.rs`: arguments, database connection, and export orchestration.
- `src/statistics/`: aggregation, support-card mapping, CSV streaming, reports, and dataset publication.
- `src/storage.rs`: JSON/gzip storage and directory replacement.
- `src/resources.rs`: resource monitoring and progress logging.
- `src/types/`: declarations grouped by domain, included by their owning modules to preserve private field visibility.

Owned functions use lowerCamelCase; CLI flags and JSON field names retain their existing spelling.

## Run

From the repository root:

```dotenv
DATABASE_URL=postgresql://user:password@127.0.0.1:5432/honsemoe_db
```

```powershell
cargo run --release
```

The CLI loads `.env` automatically for local runs. You can still pass `--database-url` or set `DATABASE_URL` in the shell if you prefer.

Useful options:

```powershell
cargo run --release -- `
  --dataset-version 2026-W19
```

For a small smoke test:

```powershell
cargo run --release -- --limit 100000
```

To watch live exporter load while a full export runs:

```powershell
cargo run --release -- --resource-usage
```

Support-card counts, skill counts, and support-card deck type combinations are generated by default. Support-card counts are aggregated by base card ID, ignoring LB/level suffixes. Deck combinations are aggregated by support-card type IDs from `src/cards.json`, stored with compact in-memory keys, and written as readable compositions such as `4xspeed_2xstamina` with a `composition` object. Distance breakdowns are bundled into `global/global.json` and each character file; standalone `distance/*.json` files are not emitted in format v4. Exported JSON is minified. `datasets.json` and each dataset `index.json` stay as plain JSON files, while heavier payload files are stored on disk as `.json.gz`.

## Docker

Build the image:

```bash
docker build -t umamoe-statistics-generator .
```

Run locally and write JSON to `./statistics`:

```bash
docker run --rm \
  --env DATABASE_URL="postgresql://user:password@host.docker.internal:5432/honsemoe_db" \
  --add-host host.docker.internal:host-gateway \
  -e UMAMOE_OUTPUT_DIR=/output/statistics \
  -v "$PWD/statistics:/output/statistics" \
  umamoe-statistics-generator
```

Run on the server and publish into both frontend roots:

```bash
docker run --rm \
  --env-file /opt/umamoe-statistics/statistics.env \
  --add-host host.docker.internal:host-gateway \
  -e UMAMOE_TARGET_ROOTS="/var/www/html/umamoe /var/www/html/umamoe_beta" \
  -v /var/www/html/umamoe:/var/www/html/umamoe \
  -v /var/www/html/umamoe_beta:/var/www/html/umamoe_beta \
  umamoe-statistics-generator
```

Run the long-lived scheduler on the server:

```bash
docker run -d \
  --restart unless-stopped \
  --name umamoe-statistics-both \
  --env-file /opt/umamoe-statistics/statistics.env \
  --add-host host.docker.internal:host-gateway \
  -e UMAMOE_RUN_MODE=scheduled \
  -e UMAMOE_TARGET_ROOTS="/var/www/html/umamoe /var/www/html/umamoe_beta" \
  -v /var/www/html/umamoe:/var/www/html/umamoe \
  -v /var/www/html/umamoe_beta:/var/www/html/umamoe_beta \
  umamoe-statistics-generator
```

The Docker wrapper uses these environment values:

| Variable | Required | Purpose |
| --- | --- | --- |
| `DATABASE_URL` | yes | PostgreSQL connection string used by the generator. |
| `UMAMOE_RUN_MODE` | no | `once` runs one export and exits. `scheduled` keeps the container alive and runs on the configured schedule. Defaults to `once`. |
| `UMAMOE_RUN_ON_START` | scheduled no | Set to `true` to run one export immediately when the scheduled container starts. |
| `UMAMOE_RUN_ON_START_DATASET_VERSION` | scheduled no | Optional dataset id for the run-on-start export only. Scheduled exports use the generator default. |
| `UMAMOE_RUN_ON_START_LIMIT` | scheduled no | Optional row limit for the run-on-start export only. Scheduled exports use the full dataset. |
| `UMAMOE_SCHEDULE_TZ` | scheduled no | Time zone for scheduled mode. Defaults to `Asia/Tokyo`. |
| `UMAMOE_SCHEDULE_DAY` | scheduled no | ISO weekday for scheduled mode, from `1` Monday through `7` Sunday. Defaults to `6` Saturday. |
| `UMAMOE_SCHEDULE_HOUR` | scheduled no | Hour of day for scheduled mode. Defaults to `0`. |
| `UMAMOE_SCHEDULE_MINUTE` | scheduled no | Minute of hour for scheduled mode. Defaults to `0`. |
| `UMAMOE_TARGET_ROOTS` | deploy yes | Space-separated frontend roots to publish into, for example `/var/www/html/umamoe /var/www/html/umamoe_beta`. |
| `UMAMOE_STATISTICS_RELATIVE_DIR` | no | Statistics directory below each target root. Defaults to `assets/statistics`. |
| `UMAMOE_OUTPUT_DIR` | no | Output directory when `UMAMOE_TARGET_ROOTS` is not set. Defaults to `/output/statistics`. |
| `UMAMOE_DATASET_VERSION` | once no | Dataset id such as `2026-W19` for one-shot mode. If omitted, the generator uses the current date. |
| `UMAMOE_LIMIT` | once no | Optional row limit for one-shot smoke runs. |
| `UMAMOE_PROGRESS_EVERY` | no | Progress logging interval. Defaults to `250000`. |
| `UMAMOE_WORKER_THREADS` | no | Parallel aggregation workers. Defaults to up to `3`; use `1` for serial mode or a higher value if the server has spare CPU. |
| `UMAMOE_BATCH_ROWS` | no | Rows per worker batch before the next trainer boundary. Defaults to `100000`. |
| `UMAMOE_RESOURCE_USAGE` | no | Set to `true` or `1` to print exporter, Postgres, and system CPU/memory at progress checkpoints. |

When publishing, each dataset is written to a hidden staging directory first, then moved into place. `datasets.json` is updated after the dataset files exist, so the frontend should not observe a new dataset before its files are ready.

## GitHub Actions Deploy

The deploy workflow mirrors the backend image flow: it builds the Docker image, ships it to the host over SSH, loads it, and starts or replaces the long-lived scheduler container against mounted frontend directories.

The workflow itself does not use a GitHub Actions timer. Scheduled runs happen inside the container every Saturday at 00:00 JST by default. Scheduled runs use the normal defaults: full dataset, deploy target `both`, 3 aggregation workers, 100000-row batches, and the dataset version generated by the exporter.

Manual runs include worker-thread and batch-size inputs plus a `run_statistics_now` checkbox. Leave the checkbox checked to deploy the Docker image, start the scheduler container, and kick off one export immediately. Uncheck it to only start or refresh the scheduler container and wait for the next Saturday run. Manual `dataset_version` and `limit` inputs apply only to that immediate run, not future scheduled exports.

Repository or environment secrets needed by `.github/workflows/deploy-statistics.yml`:

| Secret | Purpose |
| --- | --- |
| `DEPLOY_HOST` | SSH host for the server. |
| `DEPLOY_PORT` | Optional SSH port. Defaults to `22`. |
| `DEPLOY_SSH_KEY` | Private key for the `github` deploy user. |
| `DEPLOY_KNOWN_HOSTS` | Known-hosts entries for strict host verification. |

Server files expected by the workflow:

| Path | Purpose |
| --- | --- |
| `/opt/umamoe-statistics/statistics.env` | Docker env file. Must include `DATABASE_URL=...`; optional values like `UMAMOE_PROGRESS_EVERY=250000` can live here too. |
| `/var/www/html/umamoe/assets/statistics` | Production statistics target. |
| `/var/www/html/umamoe_beta/assets/statistics` | Beta statistics target. |

## Container Scheduling

Scheduled mode does not need host cron or GitHub Actions cron. Keep the container running with `--restart unless-stopped`; it sleeps until the next configured local time, runs the exporter, then waits for the next week.

## Notes

- The database password is intentionally not hardcoded. Use `DATABASE_URL` or `--database-url`.
- Names, icons, and colors are intentionally not resolved by the generator in `ids-v1`; resolve them in the frontend from local data. Support-card deck combinations use type IDs from `src/cards.json` to emit readable type compositions.
- Percentiles are exact for integer stats. The Rust port stores value frequencies instead of all 25M rows.
- The query is ordered by `trainer_id`, which lets trainer-level counts be finalized one trainer at a time without keeping trainer sets in memory.
